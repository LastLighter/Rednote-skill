# 选题挖掘：没有链接时，从哪儿找值得做的题

用户没给帖子，只说"找几个选题""这周写什么""给我排个期"——**先选题，再写稿**。跳过这一步直接写，写出来的是通用稿：谁都能发，谁都不会点。

选题模式只产出**选题卡片**，不写正文、不出图。用户点选之后，再回到 `SKILL.md` 的步骤 0。

---

## 一、什么时候走这条

| 用户给的东西 | 走哪条 |
| --- | --- |
| 一条链接 / 一段正文 | 直接进 `SKILL.md` 步骤 0 |
| 一个话题（"AI 焦虑""约会软件"） | 先挖一轮，看有几种角度，再选一条 |
| 什么都没有，让你找 | 走本文，一次给 6–10 条卡片 |
| 已有明确选题，只要成稿 | 跳过本文，进步骤 0；批量写见 `batch-production.md` |

选题前先读账号档案（没有就问四问）。**同一个爆款，测评号能做、资讯号能做、职场号只能换个角度做**——选题和定位对不上，写得多好都白发。

---

## 二、检索式：样本质量在这一步就定了

X 的高级搜索语法 + 三个质量闸门：

```
("关键词 A" OR "关键词 B") lang:en min_faves:500 since:2026-05-01 -filter:replies -filter:nativeretweets
```

| 闸门 | 作用 | 不加会怎样 |
| --- | --- | --- |
| `-filter:nativeretweets` | 去掉转推和搬运 | `queryType: Top` 被转推占满，翻出几年前的老帖 |
| `min_faves:500~800` | 只留经过验证的 | 大量零互动噪声，筛选成本高过抓取成本 |
| `since:最近 3–6 个月` | 限定时间窗 | 五年前的爆款被 Top 排序顶上来 |

**一个检索式一次运行。** 把 `["money habits","solo travel","sleep habits"]` 一起提交，actor 会当成一次查询——实测 45 条里 44 条是同一个词。

**中英文各跑一轮**：英文找原帖和一手信息，中文找这个议题在中文语境里的对应物（相亲角 / 简历化 / 大厂黑话）。中文对应物往往比英文原帖更适合小红书。

六组检索、175 条原帖，成本约 **$0.03**。选题阶段不需要全量，一组先看 30 条。

## 三、抓取

### 3.1 脚本（推荐）

```bash
set APIFY_API_TOKEN=apify_api_xxx
python scripts/x-search.py ^
  --query "(burnout OR \"return to office\") lang:en min_faves:800 since:2026-07-01 -filter:replies -filter:nativeretweets" ^
  --name work --max 30
```

Windows PowerShell 用反引号续行，或写成一行。输出 `data/x/work.json`，并在终端按**收藏/赞比**排好序打印前 12 条。

- Actor：`xquik/x-tweet-scraper`（Pay-Per-Result，约 `$0.00015/条`）
- 端点：`run-sync-get-dataset-items`，一次调用拿完整结果
- 只依赖 Python 标准库，不需要 httpx / dotenv

### 3.2 免费额度的坑

`apidojo/tweet-scraper` 有"每月 5 次运行"的隐形上限。超限后**不报错**：返回 HTTP 201 + `SUCCEEDED` + 单条 `{"noResults": true}`。看到这个形状，先怀疑额度，不要以为真的没搜到。

### 3.3 其他入口

- 已经有一条帖子 → `scripts/fetch-post.mjs`，自动展开引用链
- 想反向找空位 → `scripts/fetch-hot.mjs` 拉小红书推荐/分类热门，看同类话题写到哪一步了

## 四、排序口径：看收藏/赞，不看赞

**赞 = 路过鼓掌，收藏 = 我要存下来。** 小红书的长尾流量来自搜索和收藏，所以选题按比值排：

| 收藏/赞 | 类型 | 适合 | 排期作用 |
| --- | --- | --- | --- |
| ≥ 0.5 | 干货型 | 长尾搜索、收藏 | 沉淀 |
| 0.1–0.5 | 混合 | 看角度 | 都可 |
| < 0.1 | 情绪型 | 转发、评论、涨粉 | 拉新 |

样本里的实际值：Armstrong 1.44（收藏比赞还多）、signulll 0.61、thani 0.47、whaledev 0.79；情绪型 shaiBUTblunt 0.022、muumoonya 0.063。

**两种都要，混着发。** 只发干货涨得慢，只发情绪留不住人。

其他判据：

- **粉丝少、赞极高 = 纯共鸣**，不是大 V 效应（457 粉拿 57,386 赞，说明这句话戳中的是一批人）
- **评论区天然分裂**（一派想搞钱、一派想休息）= 互动率会好看
- **收藏绝对量过万** = 强"存档"信号，适合做长尾
- **小红书同类还停在教程侧** = 反向选题的空位
- **事件后 24–72 小时**讨论信息量最大，更晚的多是复读

## 五、一票否决：这些素材不能当事实源

### 搬运号

特征同时出现两条以上，直接弃用：

- `This is f*cking insane` 开头 + `Here are the signs:` / `Bookmark this` 结尾
- 几千粉拿几万赞，主页全是同款排版
- 同一句话在多个账号重复出现、配不同的视频（实测 "A Finnish teacher quietly solved phone addiction" 在 8 个账号上出现）

这类内容既搬运又常编造，二次搬到小红书会同时踩"搬运"和"不实信息"两条线。**同一句话在多个账号重复 = 素材，不是证据。**

### 可疑数字

出处不明的一律禁用，不要"大概差不多"地写。已知禁用项：**"Claude Code 从 18% 提升到 95%"**（出处是搬运号，原始来源不明）。

### 个人经验

"我几乎没写代码""我 4 周上了 Steam"是他个人表述，写成"他的做法"，不写成"行业标准"。先核实可核实的节点（Steam 页面、发布时间、提交次数）再动笔。

### 医疗 / 心理

只描述现象，不下诊断，不给用药建议，标题不下结论，正文带"不替代专业诊断"。**概念出处核实不了，就用"有个说法""有人把它叫"，不要写"研究表明""心理学家证明"，不要造人名和论文。**

### 引用他人帖子

截图打码，不整段搬运原文。当事人亲自发的、官方账号下场的，可以点名——那是新闻，不是搬运。

## 六、选题卡片：一条一屏，六件套

给用户的每条选题都按这个结构写。缺一件，用户就没法判断要不要做。

```markdown
### 选题 N｜一句话标题

**原始素材**
- @账号（粉丝数）：赞 / 收藏 / 浏览（日期）——"原文里最扎的那一句"

**为什么值得做**
收藏/赞 = X.XX；同类在小红书还停在 XX 侧；评论区在吵 A 和 B。

**标题候选**
1. ……（钩子：……）
2. ……（钩子：……）
3. ……（钩子：……）

**正文骨架**
现象（一句反常识的判断）→ 具体场景 → 命名/数字 → 三种改法 → 结尾提问

**配图**
图 1 封面：……｜图 2 证据：……｜图 3 收束：……

**风险**
事实（要先核什么）/ 合规（医疗、性别对立）/ 立场（落点必须是选择权）
```

一次最多给 **6–10 条**，标出推荐优先级；用户点选时一次最多定 **3 条**，避免 brief 失焦。

---

## 七、可复用的结构：高收藏选题的形状

这轮样本里收藏/赞最高的三条，结构完全一样：

> **一句反常识的判断**（不是教程）→ **一个具体到能复述的场景** → **一个被命名的概念或数字** → **落到"所以你可以改哪一件小事"**

对照：纯教程型（"5 个 AI 工具""三步戒手机"）在小红书已经产能过剩；"命名 + 场景 + 一个小改动"的收藏率明显更高。

三个可直接套的变体：

| 变体 | 例子 | 落点 |
| --- | --- | --- |
| 给感受命名 | 认知性孤独 | 原来我不是一个人 |
| 把事故翻译成你的风险 | 官网被 PHP 干停 | 你的官网也可能这样 |
| 拆穿一个流行解法 | 数字极简是新的表演 | 换默认值，不靠意志力 |

## 八、交付之后

1. 用户点选 → 进 `SKILL.md` 步骤 0（账号）→ 步骤 1（调研原文）。**选题阶段的事实只是线索，不是定稿依据**，动笔前仍要回到原帖、引用链和评论区。
2. 同一条选题写第二版，用 `-v2` 另起目录，保留对照（见 `batch-production.md`）。
3. 排期按"情绪拉新 / 干货沉淀"混排；一周 2–3 条足够，不要一次排满。
