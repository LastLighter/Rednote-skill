# 实战复盘：一条引用转发，如何变成 3 张图文

这个 case 把本 skill 的大部分坑都踩了一遍。记录下来，是为了下次少走。

---

## 起点

用户给了一条 X 链接：`https://x.com/Last_Lighter/status/2113566437776531529`

---

## 坑 1：只抓最外层帖子

**直接抓到的内容：**

> 意想不到的展开，这也能联动？

12 个字。做不了图文。

**展开引用链之后：**

```
昨日余光：意想不到的展开，这也能联动？
  └─ Vonng：一国元首竟然会发 PHP 漏洞公告和修复建议……
       └─ 高市早苗（当事人）：官网为应对 PHP 漏洞临时停机，已恢复
```

真正的素材在最底层。**教训：先展开引用链，再决定要不要做。**

---

## 坑 2：抓取工具被 fake-ip 拦下

```
Error: URL hostname "x.com" resolves to a non-public IP address
```

`x.com` 被解析到 `198.18.0.112`（TUN 代理的 fake-ip 段），工具的 SSRF 检查直接拒绝。

但 `curl` 是通的（返回 200）。改用 `api.vxtwitter.com` 拿 JSON，一次拿到正文、媒体、点赞数和 `qrt` 引用对象。

**教训：工具拦你 ≠ 网络不通，先换 curl 试。**

---

## 坑 3：照抄原帖的夸张表述

原帖说"世纪大漏洞""写的是《用漫画理解网络攻击》"。

核查后发现：

- 官方表述是"两个高危远程代码执行漏洞"，不是"世纪大漏洞"
- 书的日文原名是《サイバー攻撃から暮らしを守れ！》，"用漫画理解网络攻击"只是书中一章

**教训：梗可以留，事实必须核。核对表要附在交付物里。**

---

## 坑 4：图太多、字太多、太技术

第一版做了 8 张图，正文 500+ 字。问题：

- 8 张里有一半是"把文案拆成图"，读者不会看完
- 正文太长，手机上一屏刷不完
- 图 7 塞了 CVE 编号、影响范围、处置建议——**读者不是安全工程师**

**教训：3 张就够；正文 180 字；技术细节进置顶首评。**

---

## 坑 5：封面太空

用程序排版做封面，出来是"纯色背景 + 两行大字"。刷到时像 PPT。

改用 AI 生图后，第一版仍然空——因为提示词只说了"标题 + 一个物件"，没说"填满"。

加上四层结构（文字 / 人物 / 道具 / 散点）并明确写"画面必须被元素填满"，才解决问题。

**教训：密度是写进提示词的要求，不是模型自己会做的事。**

---

## 坑 6：数字被放错位置

对比图里要把"1946（出版社成立）"和"1995（编程语言诞生）"并列。

第一版把 `1946` 刻在书脊上 → 读者会理解成"这本书是 1946 年的"（实际书是 2018 年）。

改成在两半下方各自标注 `1946 · 出版社` / `1995 · 编程语言`，歧义才消失。

**教训：数字必须在画面里有上下文。**

---

## 坑 7：图 3 写成了"知识点"

第一版图 3 是"关站不丢人 + 四条自查动作（查版本 / 升级 / WAF / 关站）"。

**这违背了整条 SOP：** 正文说了只打一个反差、细节丢评论区，结果图 3 又把技术方案搬回来了。非技术读者卡在最后一张。

改成**故事的下一步**：

| 10/21 深夜 | 10/22 上午 | 10/22 |
| --- | --- | --- |
| 官网突然下线 | 才敢重新开放 | 她发帖：该关就关 |

零术语，全是日常动作，且收在"当事人自己承认慌了"这个最有画面感的位置。

**教训：图 3 是故事的一部分，不是知识补充。**

---

## 坑 8：把人名泛化

初稿写"日本首相的官网连夜下线了"。

改成"高市早苗这波，属实把节目效果拉满了""把高市早苗的官网干停了"之后，情绪完全不同。

**教训：已知名人用本名。泛化 = 抽干情绪。**

---

## 坑 9：主观臆断平台规则

曾判断"把政治人物肖像放进推广图有平台风险"，据此选择了卡通化。

这个判断**没有依据**，是想当然。

实际情况是：手上没有当事人的参考照片，纯文字描述只会让模型编一张不像的脸。**真正的限制是没有素材，不是平台规则。**

**教训：不要把"我没法做"包装成"规则不允许"。先区分是能力问题还是合规问题。**

---

## 最终形态

| 项 | 结果 |
| --- | --- |
| 图 | 3 张，1080×1440，扁平卡通，人设出镜 |
| 标题 | 高市早苗官网，被PHP干停了（12 字） |
| 封面大字 | 高市早苗 / 的防黑客书 ＋ 黄标签「出版社叫 PHP」 |
| 正文 | 201 字，1 个 emoji |
| 置顶首评 | CVE 编号、时间线、CERT 提示、书名 ISBN |
| 槽点 | 正文只写"严重漏洞"不给编号，等懂行的人来补 |

---

## 一页总结

1. 先展开引用链，再判断值不值得做
2. 事实核对在写文案之前
3. 3 张图，180 字，只打一个点
4. 封面要填满，封面大字不复刻标题
5. 图 3 讲故事，不讲知识
6. 名人用本名
7. 不要用"规则不允许"掩饰"我没有素材"
