# 批量成稿：一次 3 条，每条过三道闸

单帖转图文（`SKILL.md` 步骤 0–6）适合一次做一篇。要**一次交 3 条**、或跨会话把稿子攒起来时，走这个模式：选题定稿 → 一条一个子 Agent → 三道闸 → 回写状态。

规范只有一份，就是 `SKILL.md` 和 `references/`。本文不重复规范，只讲**怎么并行、怎么验收**。

---

## 一、什么时候批量

| 场景 | 做法 |
| --- | --- |
| 用户给一条链接 | 单篇，走 `SKILL.md` |
| 用户从选题卡片里点 2–3 条 | 批量，本文 |
| 用户要"这周的三篇" | 先选题（`topic-mining.md`），再批量 |
| 同一篇要第二版 | 新建 `-v2` 目录，保留上一版对照 |

一次最多 **3 条**。四条以上，brief 会串味，三篇写成一个腔调。

---

## 二、目录与状态

跨会话批量时，在工作区建一个成稿根目录，一篇一个子目录：

```
写文-成稿/
├── 001-认知性孤独/
│   └── note.md
├── 001-认知性孤独-v2/     ← 重写保留对照，不覆盖
└── 002-官网被 PHP 干停/
    └── note.md
```

命名用 `<NNN>-<中文短名>`，编号不复用。状态记在看板（或任意一张表）里：

```
待定稿 → 已定稿 → brief中 → 成稿中 → 待复核 → 待发布 → 已发布
                     ↑                  ↓
                     └──── 复核退回 ────┘
```

**每换一步先写状态，再动手。** 状态不写，换个会话就会重复出稿。

子 Agent 的写入范围只有自己那个目录的 `note.md`。**技能仓库只读**，成稿不要写进 `rednote-skill`。

---

## 三、拆 brief：一条一个子 Agent

用 `subagent`，不要用 `subagent_fork`——fork 会带上整段对话，三条稿子会互相污染语气。

子 Agent 看不到你的对话，所以 brief 必须**自包含**。五块，缺一块它就会自己编：

### 1. 素材来源

```markdown
原帖：<链接>
本地素材：D:\...\data\x\work.json（第 12 条，@signulll）
关键事实：32,463 赞 / 19,716 收藏（2026-10-17）；原文"……"
已核实的节点：……
未核实、只能软引用的：……
```

给**路径和数字**，不要给"大概是个讲 AI 的帖子"。

### 2. 技能与规范

```markdown
先加载 rednote skill（BASE：D:\DSH-workspace\rednote-skill）。
按 SKILL.md 步骤 0–6 写，规范以 SKILL.md 和 references/ 为准。
只读技能仓库，不修改、不在里面产出文件。
```

### 3. 硬约束

```markdown
- 不编造：没有出处的研究、数字、人名、评论一律不写
- 搬运号不是事实源；出处不明写"有个说法"
- 医疗/心理只描述现象，不下诊断，正文带免责
- 落点是"你可以改哪一件小事"，不是"你该怎么办"
- 第一人称，真人四段，不写"首先其次最后"
- 篇幅：≤120 字，或 ≥400 字；不要落在 200–400
- 不提原帖、不写"原帖说"、默认不写首评
```

### 4. 交付物

```markdown
只写当前目录 note.md，结构：
标题 → 3 个标题候选（各附钩子一句话）→ 开头两句 → 正文
→ 8–12 个标签 → 3 张配图方案（各自分工）→ 风险自检 → 待核实清单
```

### 5. 完成后回报

```markdown
回报：字数 / 用了哪些素材 / 哪些没核实 / 自检哪条没过。
```

---

## 四、三道闸：不合格打回，不自己改

子 Agent 交稿后，逐条过闸。**发现问题是打回重跑，不是自己动手改**——自己改，下一批还会犯同样的错。

### 闸一：事实

- [ ] 每个数字、引文、专名都能回到素材（原帖 / 引用链 / 官方页）
- [ ] 没有新造的案例、评论、研究、人名
- [ ] "最/第一/唯一"有出处，否则删掉限定词
- [ ] 时间、价格、版本号与素材一致（易漂移）
- [ ] 搬运号内容没有被当成事实

### 闸二：合规

- [ ] 医疗/心理：只描述现象，有"不替代专业诊断"
- [ ] 未核实内容写成"有个说法/有人把它叫"，不是"研究表明"
- [ ] 引用他人帖子打码，不整段搬运
- [ ] 情感类不写性别对立、不劝断交、不诊断对方人格
- [ ] 不承诺收益、不写"稳赚/必瘦/治愈"

### 闸三：规范

- [ ] 篇幅落在 ≤120 或 ≥400，没有 200–400
- [ ] 标题 12–16 字，封面大字不复刻标题
- [ ] 标签 5–8 个，不堆无关大词
- [ ] 段落 ≤4 行，首行 40 字内出钩子
- [ ] 不提原帖、不写首评、预留槽点
- [ ] 3 张图各有分工，不是同一张换滤镜

三闸全过 → 状态改 `待发布`；任一不过 → 改 `复核退回`，把**具体哪一条**写进 brief 重跑。

## 五、长文（≥400 字）的结构

小红书正文中位 91 字，长文是少数派，但收藏/赞比高。样板是 647 字的"认知性孤独"：

| 段 | 作用 | 写法 |
| --- | --- | --- |
| 1 现场 | 让人听见语气 | 一个具体场面，有对话、有动作，不总结 |
| 2 命名 | 给感受一个词 | "有个词叫……"（概念出处核实不了就软引用） |
| 3–4 场景 | 证明不是个例 | 3–4 个同构场景，每个 2–3 句，不铺排 |
| 5 解释 | 把矛头从人转向结构 | "变的是话题密度，不是你们的关系" |
| 6 出路 | 给选择权，不给命令 | 三条，语气是"可以试试"，不是"你应该" |
| 7 免责 | 一句人话 | "这篇不替代专业诊断" |
| 8 收尾 | 提问 | 一个能答"是/不是"的具体问题 |

**长文不是把短文拉长**：多出来的是场景和解释，不是形容词。每段 ≤4 行，手机上一屏能读完一段。

`note.md` 是工作稿，交付时仍按 `SKILL.md` 步骤 6：**标题和正文直接给在对话里**，不额外生成 md 文件。

## 六、批量常见失败

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 三篇一个味 | 用了 `subagent_fork`，或 brief 共用一段 | 一条一个 `subagent`，brief 各写 |
| 子 Agent 编了研究 | brief 没给素材路径，只给了"话题" | 素材块给绝对路径 + 原文摘录 |
| 反复返工同一处 | 复核时自己改了，没回写 brief | 打回并写明"第几条不过" |
| 换会话重复出稿 | 看板没更新 | 每步先写状态 |
| 成稿散落 | 写进了技能仓库或临时目录 | 固定成稿根目录，编号不复用 |
| 标签越写越多 | 想蹭流量 | 5–8 个，只留和正文强相关的 |

---

## 七、交付

1. 三篇都过闸 → 一次性给用户：每篇标题 + 正文 + 3 张图，标明推荐顺序。
2. 有退回的 → 先给过的，退回的单列，写清"等补充素材/等确认事实"。
3. 发布后回写 `已发布`，并把实际数据（赞/藏/评）记一行——下一轮选题的比值判断就有了自己的样本。
