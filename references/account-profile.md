# 账号档案：四问、模板、示例

文案不是"写给所有人看的一篇字"，是"**这个号**写给**这批人**的一条笔记"。同一件事，账号不同，写成完全不同的东西。

档案就是把这个"不同"固定下来，免得每篇都从头猜。

---

## 一、四问（一次问完）

| # | 问题 | 追问（答得含糊时） | 问够了的标准 |
| --- | --- | --- | --- |
| 1 头像 | 有固定头像 / 人设图吗？ | 是真人、卡通形象，还是纯文字头像？ | 知道封面要不要出人、出什么人 |
| 2 简介 | 账号简介现在怎么写的？ | 想不出简介，就问他"你希望别人一看简介知道什么" | 知道口吻强度和不能说的话 |
| 3 面向谁 | 写给谁看？ | "年轻人"→ 学生还是上班？几岁？他最烦这件事的哪一点？ | 具体到一个身份 + 一个处境 + 一个痛点 |
| 4 什么领域 | 这个号做什么内容？ | 说不清就让他举 3 条最近发的笔记 | 能说清"能发什么、不能发什么" |

**一条消息问完，等一轮回答。** 不要问一条等一条，也不要问完再补问。

问法照抄：

> 开始前确认一下账号：① 有固定头像 / 人设图吗（有就发我）？② 简介现在怎么写的？③ 主要写给谁看？④ 这个号做什么领域的内容？

### 什么叫"问够了"

| 太糊 | 够用 |
| --- | --- |
| 写给学生看 | 写给学生党，尤其是想白嫖会员又怕封号的 |
| 做科技内容 | 做 AI 工具测评，主要测国内能直接用的 |
| 分享职场经验 | 写给工作 1–3 年、想跳槽又不敢跳的人 |
| 随便发点 | （这种要停下来：没有定位就没有"这个号为什么发这条"） |

受众越小，文案越准。**"所有人"等于没有人。**

## 二、档案模板

存到工作目录的 `.rednote/account.md`：

```markdown
# 账号档案

- 账号名：
- 头像 / 人设：无｜有（`.rednote/avatar.png`：卡通形象，黑色短发、圆框眼镜、米白针织衫）
- 简介：
- 面向谁：（身份 + 处境 + 痛点）
- 领域：
- 内容比例：（可选，例：70% 模型测评 / 30% 行业八卦）
- 口吻：（可选，例：第一人称、敢下判断、不端着）
- 标签池：
  - 大词：
  - 中词：
  - 长尾：
  - 自造词：
- 禁区：（不碰的：未证实爆料、品牌拉踩、带货承诺……）
- 更新于：YYYY-MM-DD
```

只填前五项也能开工；`标签池`和`禁区`是写了几篇之后自然长出来的，写完一篇可以把新词补回去。

## 三、三个示例档案（示例，不是标准答案）

### A. AI 测评号

```markdown
- 头像：卡通形象，戴眼镜的短发女生
- 简介：自己掏钱测 AI 工具，只说难听的真话
- 面向谁：写代码的、做设计的，日常已经在用 AI，但被"号称最强"骗过几次
- 领域：模型 / 工具横向对比，以实测画面为准
- 口吻：第一人称，敢下判断，允许吐槽
- 标签池：大词 #AI #人工智能；中词 #大模型 #AI绘画；长尾 #模型对比 #提示词；自造词 #我测给你看
```

写出来是："同一个提示词，一个能开箱一个只会站着"——**下判断、给对比、术语可以留**。

### B. 泛科技资讯号

```markdown
- 头像：无，纯排版封面
- 简介：每天三分钟，看懂科技圈发生了什么
- 面向谁：非技术岗上班族，通勤路上刷手机，不懂代码但怕落伍
- 领域：科技事件、公司动态、产品发布
- 口吻：讲人话，不下技术结论，只讲"发生了什么、跟你有啥关系"
- 标签池：大词 #科技 #互联网；中词 #科技新闻 #数码；长尾 #今天发生了什么；自造词 #三分钟看懂
```

写出来是："官网被黑，连夜下线"——**讲事件、零术语、给"跟我有关"的那一句**。

### C. 职场效率号

```markdown
- 头像：真人半身照（不用 AI 重绘）
- 简介：教你把活干完准时下班
- 面向谁：工作 1–3 年的白领，活多、工具乱、怕被优化
- 领域：效率工具、工作流、职场沟通
- 口吻：像同事聊天，给具体动作，不灌鸡汤
- 标签池：大词 #职场 #效率；中词 #打工人 #办公技巧；长尾 #摸鱼神器；自造词 #准时下班
```

写出来是："你的官网，也可能是这样被搞停的"——**把别人的事故翻译成读者的风险**。

## 四、同一件事，三种写法

同一件"某产品官网被黑、连夜下线"，三个号写出来：

| | A 测评号 | B 资讯号 | C 职场号 |
| --- | --- | --- | --- |
| 标题 | 官网被黑，这产品连夜拔网线 | 昨晚，某官网突然打不开了 | 你的官网，也可能这样被搞停 |
| 首句 | 我熬到两点看它下线 | 昨晚十一点，页面开始报错 | 别笑，这事离你不远 |
| 术语 | 可以直接说漏洞类型 | 一个都不留 | 只留"被黑" |
| 结尾问 | 这算不算年度最离谱的事故？ | 你昨天刷到没？ | 你们公司官网谁在管？ |
| 图 3 | 技术时间线 | 事件后续 | 三步自查清单 |

**事实是同一份，写出来没有一句重合。** 这就是档案的作用。

## 五、没有头像怎么办

三选一，选了就固定，不要每篇换：

1. **造一个固定卡通形象**（推荐）——系列感最强，也规避真人肖像问题。生成后存成 `.rednote/avatar.png`，之后每次作为参考图1。
2. **纯排版封面**——大字 + 高饱和色块 + 一个图标，不出人。适合资讯号、书单号。
3. **只出手 / 背影 / 侧脸**——辨识度弱，适合产品、物件为主的内容。

反面：每篇临时生成一张新脸。读者认不出你，等于没有账号。

## 六、常见错误

| 错误 | 后果 | 改法 |
| --- | --- | --- |
| 问了不落盘 | 下一篇又问一遍，用户烦 | 确认完立刻写 `.rednote/account.md` |
| 受众写"所有人" | 谁都不觉得是写给他的 | 具体到身份 + 处境 + 痛点 |
| 把定位写进正文 | "作为一个 AI 博主…"，AI 味最重的一句 | 定位只在内部用，正文只讲事 |
| 定位和选题打架还硬发 | 号越做越杂，标签乱 | 先说清"这个号为什么发这条"，说不清就不发 |
| 改了定位没改标签池 | 推荐池还是老的那批人 | 标签池跟着定位一起更新 |
| 头像每篇一换 | 没有账号记忆点 | 定一张，长期用 |
