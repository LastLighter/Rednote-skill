# 生图提示词

## 一、提示词骨架

按这个顺序写，模型最容易理解：

```
1. 画幅与构图     3:4 竖版构图。画面必须被元素填满，不允许大面积空白。
2. 参考图         参考图1的卡通角色，保持发型、眼镜、服装与画风一致；参考图2 起是原帧，原样贴进屏幕，只许等比缩放。
3. 分区描述       左下方 / 右下方 / 中部 / 上方，每区写清"谁、在哪、什么动作、什么表情"
4. 文字           巨大的中文大字两行"XX""XX"，超粗纯黑黑体，被人物轻微遮挡
5. 色块标签       一枚高饱和亮黄色圆角矩形色块，色块内是黑色超粗字"XX"
6. 背景           浅灰蓝色，被元素填满，几乎看不到空白
7. 风格           扁平矢量卡通，粗描边，均匀柔和光，不要渐变光效，不要照片质感
8. 边距与禁令     所有关键元素距四边 ≥ 5%；除上述文字外不要出现任何其他文字
```

---

## 二、必须写进提示词的六句话

这几句是从翻车案例里换来的，缺一句就多一次返工：

| 句子 | 不加的后果 |
| --- | --- |
| `画面必须被元素填满，不允许大面积空白` | 出来一张"背景 + 两行字"的 PPT |
| `除上述文字外，不要出现任何其他文字、单词或乱码` | 画面被乱码英文单词塞满（oven / that / kdi…） |
| `所有中文必须完整显示在画面内，四周留足边距，不得裁切` | 标题撑出画面被切掉 |
| `三张卡片高度完全一致、顶部对齐、底部对齐、字号一致` | 卡片高矮不齐，字号忽大忽小 |
| `不要渐变光效，不要粒子，不要数据流` | 廉价全息感 |
| `扁平矢量卡通，粗描边` | 画风跑偏成写实 3D |

## 三、负向约束怎么写

模型对"不要"的响应弱于对"要"的响应。**先正面描述，再用一句总禁令收口。**

推荐写法：

```
画面中除了"高市早苗""的防黑客书""出版社叫 PHP"这三组指定文字之外，
不要出现任何其他可读的文字、单词、字母串或乱码，散落元素保持纯图形。
```

散落元素要**指定种类**，否则模型自由发挥：

```
散落的小元素只有这几种：透明的碎玻璃片、荧光绿纯色小方块、单个大写字母 P/H/P。
```

## 四、中文文字：最容易翻车的地方

- 文字一定要**用引号圈死**，逐字给出
- 生成后**逐字核对**，尤其注意：多一横、少一点、形近字
- 一次不要超过 3 个文字块，超过就容易错
- 长句拆短，"出版社叫 PHP" 比 "这本书的出版社名字恰好也是 PHP" 稳得多

核对清单：

- [ ] 大字逐字正确
- [ ] 色块标签逐字正确
- [ ] 数字/年份没被改写
- [ ] 没有多余的文字块

---

## 五、常见翻车与对策

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 背景变白 / 变亮 | 没写死背景色 | 明确写"深色/浅色 ×××"，并强调"与系列统一" |
| 标题被裁 | 没给安全区 | 写"四周留足边距，不得裁切"，并降低字号要求"中等偏大，不撑满画面" |
| 卡片高矮不齐 | 没约束对齐 | 写"高度完全一致、顶部对齐、底部对齐、字号一致" |
| 乱码英文满天飞 | 没禁其他文字 | 加总禁令 + 指定散点元素种类 |
| 语义错位 | 数字没说明含义 | 数字要写明所指，例如"1946 · 出版社"而不是把 1946 刻在书脊上 |
| 人物左右横跳 | 没指定方向 | 每张都写清"位于画面右侧/左下方" |
| 画风不统一 | 各张提示词风格描述不一致 | 把风格那一段做成固定模板，每张照抄 |

**"语义错位"是最隐蔽的一种**：把出版社成立年份刻在书上，读者会以为那是出版年份。数字/年份必须在画面里带上下文。

## 六、参考图（人设 + 原帧）

参考图有两类，可以同时传，顺序有讲究：

| 顺序 | 类型 | 作用 |
| --- | --- | --- |
| 参考图1 | 账号人设图 | 保持人物画风一致 |
| 参考图2 起 | 原帖关键帧 | 把真实画面嵌进图里，保证证据不被重画 |

```bash
node scripts/imagen.mjs \
  --prompt-file prompts/01-cover.md \
  --out-dir out/ \
  --ref .rednote/avatar.png \
  --ref refs/opus.png --ref refs/deepseek.png \
  --ratio 3:4 --tier 2k
```

### 6.1 人设

```
参考图1的卡通角色形象，保持黑色短发、圆框眼镜、米白色针织毛衣的造型与扁平卡通画风完全一致，只画上半身。
```

不要复述参考图里所有细节，一句"保持一致"即可。

人设图取自 `.rednote/avatar.png`（见 `account-profile.md`）。档案里没有头像、走排版路线时，这一段和 `--ref` 一起删掉——不要临时生成一张脸硬凑，每篇换一张脸等于没有账号。

### 6.2 原帧（真实感的关键）

原帧是"证据"，提示词必须写成禁止重画，而不是"参考风格"：

```
参考图2 和参考图3 是模型的真实输出截帧，属于证据，不要重画。
参考图2 原样贴进左侧大屏幕里：像素画面、中文对话框、宝箱、角色、配色全部保持一模一样，
只允许等比缩放，不允许重绘、改字、加滤镜、加光效。
参考图3 原样贴进右侧小屏幕里，同样只允许等比缩放。
两块屏幕外要有厚实的深色边框，屏幕内保持像素原样。
```

要点：

1. **说"原样/一模一样/不要重画"**，而不是"参考这张图的风格"——后者会得到一张重绘的插画。
2. **明确哪张图放在哪个位置、多大**，不然模型会把两张拼成一张。
3. **明确"只允许等比缩放"**，不然会拉伸变形。
4. **保留原帧自带的文字**：哪怕糊了、是英文、是乱码，那也是证据。禁令只针对屏幕外新增的文字。

### 6.3 原帧翻车与对策

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 屏幕里变成"同风格插画" | 只写了"参考图"，没写"原样贴入" | 加"原样、一模一样、只许等比缩放、不要重绘" |
| 原帧被裁掉一半 | 没说屏幕比例 | 写明"屏幕内容按比例完整显示，不要裁切" |
| 原帧被加了滤镜/光效 | 风格段落把屏幕也算进去了 | 加"屏幕内保持像素原样，不要美化" |
| 屏幕里的字被"翻译"或改写 | 没锁文字 | 加"屏幕里的文字必须是参考图里本来就有的内容" |
| 两张参考图被拼在一起 | 没指定位置 | 逐张写清"参考图2 在左、参考图3 在右" |

> 判断标准：成图里的那一块，放大后应该能跟原帧对得上——像素位置、文字、配色都能对上，才算过。

### 6.4 选模型：优先 gpt-image-2

| 模型 | 画面 | 原帧保真 | 结论 |
| --- | --- | --- | --- |
| **gpt-image-2** | 最强：字体粗黑、构图稳、色彩准 | 中：会把原帧里的数字/字母重排（实测把「© 2026」写成「© 2025」） | **默认首选** |
| nano-banana-2 | 偏软，字偏圆 | 高：连糊掉的 HUD、故障重影都原样保留 | 原帧里有必须逐字保真的内容时用它 |
| grok-imagine-image / Wai-SDXL / Z-Image-Turbo / Qwen-Image-Edit | 风格化 | — | 特殊需求才用 |

注意：`gpt-image-2.5` 在 imagifly 上**不存在**（可用模型只有 gpt-image-2、nano-banana-2、grok-imagine-image、Wai-SDXL-V150/V170、Qwen-Image-Edit、Z-Image-Turbo）。

规则：

1. 默认 `--model gpt-image-2`（提示词里写清字体要"超粗黑体"，不然中文会偏细）。
2. 图里带原帧 → 出图后**放大原帧区域逐字比对**；只出现个别数字被改、且不影响结论时，可接受；一旦改到年份、版本号、对话框文案这种硬信息，换 nano-banana-2 重出。
3. 原帧区域本来就是乱码/糊字 → 必须保持"同样糊"，模型把它"修清楚"了也算失真。

## 七、输出规格

| 项 | 值 |
| --- | --- |
| 画幅 | 3:4 |
| 输出档位 | 2k（约 3584×4800）或 1k（约 896×1200） |
| 成图 | 1080 × 1440 |
| 格式 | JPEG，quality ≥ 92 |

模型常把 JPEG 存成 `.png` 扩展名，读取前先验文件头：

```powershell
$b = [System.IO.File]::ReadAllBytes($f)
($b[0..3] | % { $_.ToString("X2") }) -join ' '
# FF D8 FF E0 → JPEG
```

## 八、出图后必做

1. 逐张看，核对中文
2. 有原帧的图，把成图里的那一块放大，跟原帧逐处比对：像素画面、文字、配色、构图有没有被重画或美化
3. 检查是否满构图
4. 检查三张的画风、底色、人物位置是否统一
5. 不满意就重生成——**不要用"差不多"的图**
